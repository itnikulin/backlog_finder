# Настройка Product Backlog Advisor

Эта инструкция подключает Kilo Code к двум независимым системам:

1. Kaiten API предоставляет актуальный бэклог.
2. Внутренняя ИИ-модель анализирует полученные данные.

Данные проходят по следующему маршруту:

```text
Kaiten → локальный MCP → Kilo Code → внутренняя ИИ-модель
```

Публичные модели и Kilo Gateway для этого сценария не используются.

## 1. Что понадобится

- Node.js 20 или новее;
- Kilo Code для VS Code либо Kilo CLI;
- доступ к репозиторию `itnikulin/backlog_finder`;
- сетевой доступ к корпоративному домену Kaiten;
- сетевой доступ к endpoint внутренней ИИ-модели;
- отдельный API-ключ Kaiten;
- отдельный API-ключ внутренней ИИ-модели.

Перед началом уточните у службы информационной безопасности, разрешает ли корпоративная политика обрабатывать данные Kaiten выбранной внутренней моделью.

## 2. Установить проект

```bash
git clone https://github.com/itnikulin/backlog_finder.git
cd backlog_finder
npm install
npm test
npm run check
```

Ожидаемый результат: тесты и проверка синтаксиса завершаются без ошибок.

## 3. Создать отдельный ключ Kaiten

API-ключ можно получить в настройках личного профиля Kaiten. Откройте меню профиля, перейдите в его настройки и найдите раздел API-ключа.

Для рабочего контура рекомендуется:

- использовать отдельную техническую учётную запись, если это поддерживают ваши корпоративные правила;
- дать ей доступ только к нужным пространствам и доскам;
- не использовать ключ администратора;
- назвать ключ так, чтобы было понятно его назначение, например `backlog-finder-readonly`;
- сохранить ключ в корпоративном хранилище секретов.

Текущая версия агента предоставляет только операции чтения. Однако права самого Kaiten-токена также следует ограничить настолько, насколько позволяет Kaiten и ваша модель доступа.

Не вставляйте ключ в этот репозиторий, сообщения агента или `kilo.jsonc` открытым текстом.

## 4. Получить доступ к внутренней ИИ-модели

У владельца внутренней AI-платформы запросите:

- `base URL` OpenAI-compatible endpoint, например `https://internal-ai.company.ru/v1`;
- API-ключ;
- идентификатор модели;
- размер контекстного окна;
- подтверждение поддержки tool calling.

Tool calling необходим, чтобы модель могла вызывать read-only инструменты Kaiten MCP.

## 5. Передать ключи через окружение

В терминале, из которого запускается Kilo Code, установите переменные:

```bash
export KAITEN_BASE_URL="https://your-company.kaiten.ru"
export KAITEN_API_TOKEN="ваш-отдельный-kaiten-token"
export INTERNAL_AI_API_KEY="ключ-внутренней-модели"
```

Проверить наличие переменных без вывода секретов:

```bash
test -n "$KAITEN_BASE_URL" && echo "KAITEN_BASE_URL: OK"
test -n "$KAITEN_API_TOKEN" && echo "KAITEN_API_TOKEN: OK"
test -n "$INTERNAL_AI_API_KEY" && echo "INTERNAL_AI_API_KEY: OK"
```

Переменные действуют только в текущей терминальной сессии. Для постоянной работы используйте одобренное корпоративное хранилище секретов. Не добавляйте реальные значения в `.env.example`.

Если вы используете расширение VS Code, запустите редактор из этого же терминала командой `code .`. VS Code, открытый из Dock или меню приложений, может не получить переменные текущей shell-сессии.

## 6. Настроить глобальную конфигурацию Kilo

Откройте глобальную конфигурацию:

```text
~/.config/kilo/kilo.jsonc
```

Если файла нет, создайте его. Перенесите в него настройки из:

```text
config/kilo.global.example.jsonc
```

В скопированной конфигурации замените:

1. `https://replace-with-internal-ai.example/v1` на адрес внутреннего endpoint.
2. Все вхождения `replace-model-id` на ID внутренней модели.
3. `/ABSOLUTE/PATH/TO/backlog_finder` на абсолютный путь к клонированному репозиторию.
4. Размеры `context` и `output`, если они отличаются у вашей модели.

Оставьте ссылки на секреты без изменений:

```json
"apiKey": "{env:INTERNAL_AI_API_KEY}"
```

```json
"environment": {
  "KAITEN_BASE_URL": "{env:KAITEN_BASE_URL}",
  "KAITEN_API_TOKEN": "{env:KAITEN_API_TOKEN}"
}
```

Глобальная конфигурация используется потому, что Kilo разрешает подстановку секретов `{env:...}` только из доверенного конфига. Проектный конфиг не должен содержать реальные ключи.

Если глобальный `kilo.jsonc` уже содержит другие настройки, объедините объекты `provider` и `mcp`, не заменяя весь файл.

## 7. Включить проектные правила

Из корня репозитория выполните:

```bash
cp kilo.project.example.jsonc kilo.jsonc
```

Файл `kilo.jsonc` исключён из Git. Он подключает правила безопасности проекта и разрешает агенту пользоваться read-only инструментами Kaiten.

## 8. Исключить внешний inference

В Kilo Code проверьте:

- основная модель относится к provider `internal-ai`;
- `small_model` использует тот же внутренний provider;
- Kilo Gateway отключён или выполнен выход из аккаунта Gateway;
- autocomplete отключён либо использует разрешённую внутреннюю модель;
- в списке доступных providers нет публичного fallback;
- remote и cloud agent modes выключены для этого проекта.

Не начинайте работу с реальным бэклогом, пока не проверен маршрут сетевых запросов.

## 9. Проверить MCP

В терминале:

```bash
kilo mcp list
```

Сервер `kaiten` должен отображаться как подключённый. Он предоставляет шесть инструментов:

- `list_spaces`;
- `get_space`;
- `list_cards`;
- `get_card`;
- `get_card_comments`;
- `get_card_location_history`.

Если сервер не подключился, проверьте абсолютный путь к `src/server.mjs`, наличие переменных окружения и доступ к домену Kaiten.

## 10. Заполнить паспорт продукта

Откройте `context/product-passport.md` и заполните минимум:

- продукт и целевые пользовательские сегменты;
- основную проблему пользователя;
- от трёх до пяти outcomes;
- метрики и их источники;
- обязательные сроки и ограничения;
- доступную ёмкость команды;
- ID пространств и досок Kaiten;
- соответствие custom properties продуктовым целям и оценкам.

Не копируйте в паспорт весь бэклог. Kaiten остаётся источником актуальных карточек.

## 11. Первый запуск

1. Откройте репозиторий в VS Code с Kilo Code.
2. В селекторе агентов выберите `backlog-advisor`.
3. Начните с проверки доступа:

```text
Покажи доступные пространства Kaiten. Не загружай карточки и не изменяй данные.
```

4. Найдите нужную доску и выполните первый анализ:

```text
Проанализируй открытые карточки доски <BOARD_ID>. Сначала покажи качество данных,
дубли, карточки без outcome и отсутствующие оценки. Kaiten не изменяй.
```

5. После заполнения паспорта запустите приоритизацию:

```text
/prioritize-backlog для доски <BOARD_ID>. Исключи завершённые карточки.
Покажи расчёт, уверенность, зависимости и предлагаемый пакет изменений.
```

6. Для roadmap используйте:

```text
/build-roadmap для доски <BOARD_ID> на ближайшие шесть месяцев.
Используй Now / Next / Later и привяжи каждую группу к outcome и метрике.
```

## 12. Что агент может делать сейчас

Агент может:

- читать пространства, карточки, комментарии и историю перемещений;
- оценивать качество бэклога;
- классифицировать и приоритизировать работу;
- собирать outcome-based roadmap;
- предлагать изменения в формате change set;
- после подтверждения обновлять локальный паспорт продукта и Decision Log.

Агент не может:

- создавать или закрывать карточки Kaiten;
- менять приоритет, статус, сроки или исполнителя;
- добавлять комментарии в Kaiten;
- выполнять операции удаления.

Write-инструменты будут добавлены на этапе оператора после проверки качества рекомендаций и утверждения правил подтверждения и аудита.

## 13. Типовые ошибки

### `KAITEN_API_TOKEN is required`

Kilo не передал переменную MCP-процессу. Проверьте блок `mcp.kaiten.environment` в глобальном Kilo-конфиге и перезапустите Kilo из терминала с установленными переменными.

### `Kaiten API 401`

Токен неверен, отозван или скопирован не полностью. Создайте новый ключ и обновите значение в хранилище секретов.

### `Kaiten API 403`

У пользователя токена нет доступа к выбранному пространству или доске.

### `Kaiten API 429`

Достигнут лимит запросов. MCP повторяет часть запросов автоматически, но следует сузить пространство анализа или уменьшить количество страниц.

### Агент не видит `backlog-advisor`

Убедитесь, что файл `.kilo/agents/backlog-advisor.md` находится в репозитории, затем начните новую сессию Kilo.

### Запросы уходят не во внутреннюю модель

Остановите работу с реальными данными. Проверьте `model`, `small_model`, autocomplete, список providers и состояние входа в Kilo Gateway.

## 14. Проверка перед реальными данными

- [ ] Kaiten-токен создан отдельно и имеет минимальные права.
- [ ] Ключ внутренней модели хранится вне Git.
- [ ] В глобальном Kilo-конфиге указан внутренний endpoint.
- [ ] Основная и малая модели используют `internal-ai`.
- [ ] Kilo Gateway, remote mode и публичные fallback отключены.
- [ ] MCP показывает только шесть read-only инструментов.
- [ ] `product-passport.md` заполнен.
- [ ] Первый запуск ограничен одной тестовой доской.
